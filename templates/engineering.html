1. Feature Store Registry & Training-Serving Skew Avoidance

Centralized feature management guarantees identical mathematical feature transformations between training time (batch offline) and real-time inference (online REST endpoint).

{% for feat in features %} {% endfor %}

How Training-Serving Skew is Avoided: All online REST requests pass through ml.feature_store.validate_and_transform_online_payload(), which computes identical non-linear transformations (e.g. Fertilizer / Area, log1p(Area)) and validates feature distributions against historical training quantiles before feeding into the estimator.
